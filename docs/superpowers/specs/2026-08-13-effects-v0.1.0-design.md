# libgdx-agent-effects v0.1.0 Design

**Status:** Approved scope — diagnostics + deterministic preview + pixel comparison; single
fullscreen shader; hand-rolled FrameBuffer passes on libGDX primitives.

## Goal

Ship the first publishable increment of `libgdx-agent-effects`: a Java 25 library that lets a live
libGDX game, a Java test, or a coding agent declare a fullscreen effect shader, compile it into
structured diagnostics, render it deterministically off-screen, and compare the framebuffer output
against a reference within a bounded tolerance — all through the same closed, bounded contract the
rest of the teemuki8 stack uses.

## Context

The teemuki8 stack already gives agents declarative UI (`libgdx-ui-markup`), semantic UI automation
(`libgdx-ui-harness`), fixed-tick gameplay (`libgdx-agent-gameplay`), and typed state evidence
(`libgdx-agent-runtime`). Rendering is the one layer with no declarative or verifiable abstraction:
today a game draws with default-shader `SpriteBatch`, and an agent authoring a shader gets only a raw
GLSL log string back, no headless preview, and no pixel-level assertion primitive. v0.1 closes the
highest-signal gap first: **make shader compilation structured and shader output verifiable**.

## v0.1 scope — in

1. Declarative effect model (JDK-only): a named effect with vertex+fragment GLSL source and a
   bounded set of uniform bindings.
2. Structured shader diagnostics: compile result, severity-tagged messages with line numbers,
   active uniforms and attributes, and a bounded info log — never the raw log string as the contract.
3. Deterministic headless preview: render the effect to a bounded `FrameBuffer` under a fixed
   resolution and fixed `u_time`, capture pixels to a JDK-only RGBA image, and (optionally) emit a
   PNG. Mirrors the stack's `--smoke N --screenshot` convention.
4. Pixel comparison: expected-vs-actual over packed RGBA with a per-channel tolerance, explicit
   include/ignore region masks, and bounded summary statistics (differing pixels, max error, mean
   error, percent over threshold).
5. A closed stdio MCP surface exposing compile, preview, and compare tools.
6. A real LWJGL3 qualification fixture under Xvfb.

## v0.1 scope — out (deferred, in priority order)

- Multi-pass render graph (chained `FrameBuffer` passes).
- Particles (`ParticleEffect`/`ParticleEmitter`).
- Stock effects (bloom, blur, vignette).
- Hot reload of GLSL sources.
- Runtime-authority correlation (`effects-agent-runtime` adapter module).
- Android / iOS / GWT backends (LWJGL3 desktop only, matching `libgdx-ui-harness`).
- Network transport or remote process attachment (stdio MCP only, process-local).
- Guaranteed original-source line mapping (driver-reported line numbers are best-effort; GL
  preprocesses source before compiling).
- An LLM or any inference; the library executes no model and inspects no arbitrary object.

## Architecture

Five modules, one unpublished fixture. Module direction is strict and mirrors `libgdx-agent-runtime`:

```text
effects-mcp -> effects-protocol -> effects-core <- effects-libgdx
effects-fixtures -> (full stack, never published)
```

| Module | Responsibility | JDK-only? | Published |
| --- | --- | --- | --- |
| `effects-core` | Effect model, limits, diagnostic parser, pixel comparison | yes | `agent-effects-core` |
| `effects-protocol` | Bounded JSON commands/results, closed schema | no (Jackson) | `agent-effects-protocol` |
| `effects-libgdx` | Render-thread compile, preview, pixel capture | no (libGDX) | `agent-effects-libgdx` |
| `effects-mcp` | Closed stdio MCP tool catalog | no (MCP SDK) | `agent-effects-mcp` |
| `effects-fixtures` | Deterministic LWJGL3 qualification | no | no |

Packages under `io.github.teemuki8.libgdx.agent.effects.{core,protocol,libgdx,mcp,fixtures}`.

### Why the model and parser live in `effects-core`

`ShaderSource`, `EffectDescription`, `UniformValue`, `RgbaImage`, `ShaderDiagnostic`,
`ShaderDiagnosticParser`, `PixelComparisonSpec`, `PixelComparisonResult`, and `PixelComparer` are all
pure data or pure string/array math. Keeping them JDK-only means they are unit-testable with no GL
context and serializable by `effects-protocol` without pulling libGDX into the protocol module. The
render-thread layer only *produces* raw driver strings and pixel buffers and feeds them to core.

## Core data model

All public records are immutable, validate and defensively copy on construction, and reject unknown
or oversized input. Hard limits come from one `EffectsLimits` instance.

- `EffectsLimits` — bounded limits: `maxShaderSourceChars`, `maxUniformCount`, `maxPassCount`
  (reserved), `maxTexturePixels`, `maxDiagnosticChars`, `maxRenderWidth`, `maxRenderHeight`,
  `maxRegionCount`. Static `developmentDefaults()`. Validating constructor (strictly positive,
  capped).
- `ShaderSource(String vertex, String fragment)` — non-null, non-empty fragment, both within
  `maxShaderSourceChars`.
- `UniformValue` — closed union: `float`, `int`, `vec2`, `vec3`, `vec4`, `mat4`, `sampler2d`.
  `sampler2d` carries an `RgbaImage` input texture (deterministic input).
- `UniformBinding(String name, UniformValue value)` — GLSL-identifier name, count bounded.
- `EffectDescription(String name, ShaderSource shader, List<UniformBinding> uniforms,
  int renderWidth, int renderHeight, float timeSeconds)` — bounded name, bounded uniforms,
  render size within limits, finite time. `timeSeconds` is the fixed `u_time` for deterministic
  preview.
- `RgbaImage(int width, int height, int[] pixels)` — packed RGBA8888, defensive copy, `getPixel`,
  `copy`.
- `ShaderDiagnostic(boolean compiled, List<DiagnosticMessage> messages,
  List<ActiveUniform> uniforms, List<ActiveAttribute> attributes, String infoLog)` —
  `infoLog` truncated to `maxDiagnosticChars`.
- `DiagnosticMessage(Severity severity, int line, String text)` — `line` is `-1` when unknown.
- `ActiveUniform(String name, String type, int size)`, `ActiveAttribute(String name, String type)`.
- `ShaderDiagnosticParser` — JDK-only: `parse(boolean compiled, String rawLog,
  List<ActiveUniform>, List<ActiveAttribute>, EffectsLimits)` turns a driver log into
  `ShaderDiagnostic` with severity-tagged, line-mapped messages; truncation and stable ordering
  guaranteed. Unit-testable with fixture log strings.
- `PixelComparisonSpec(int tolerancePerChannel, List<Region> includeRegions,
  List<Region> ignoreRegions)` — `Region(int x, int y, int width, int height)`; bounded region
  count; empty include list means "whole image".
- `PixelComparisonResult(boolean pass, long differingPixels, int maxChannelError,
  double meanChannelError, double percentOverThreshold, long comparedPixels)`.
- `PixelComparer` — JDK-only: `compare(RgbaImage expected, RgbaImage actual,
  PixelComparisonSpec, EffectsLimits)`. Requires equal dimensions (typed failure otherwise).
  Deterministic; ignores masked regions from both numerator and denominator.
- `EffectsException(Kind)` — typed failure with stable kind (e.g. `INVALID_EFFECT`,
  `COMPILE_FAILED`, `DIMENSION_MISMATCH`, `LIMIT_EXCEEDED`, `WRONG_THREAD`). No serialized stack
  traces across protocol/MCP boundaries.

## Render-thread layer (`effects-libgdx`)

All GL work is confined to the application render thread. The layer never owns the loop, the
`ApplicationListener`, input, assets, or disposal; it wraps libGDX primitives (`ShaderProgram`,
`FrameBuffer`, `SpriteBatch`, `Pixmap`) and does not fork or patch libGDX.

- `EffectCompiler` (render-thread) — compiles a `ShaderProgram` from `EffectDescription`,
  collects `getLog()`, `getUniforms()`, `getAttributes()`, and delegates to
  `ShaderDiagnosticParser` to produce a `ShaderDiagnostic`. Returns a render-thread-only
  `CompiledEffect` handle (the `ShaderProgram` plus its resolved uniform locations) when
  `compiled == true`.
- `PreviewRenderer` (render-thread) — renders a fullscreen quad through the compiled effect to a
  bounded `FrameBuffer` at `EffectDescription`'s fixed resolution, binds `u_time`/`u_resolution`
  and any `sampler2d` uniforms, captures the framebuffer via `Pixmap.createFromFrameBuffer`, and
  converts it to an `RgbaImage`. Deterministic given the same description (fixed time, fixed
  size, fixed input textures, fixed geometry).
- `PreviewPngWriter` (render-thread) — optional bounded PNG emission from an `RgbaImage`
  (`Pixmap.write`, or a `Pixmap` reconstructed from the RGBA buffer), for screenshot evidence.
- `EffectsLibGdxLimits`/lifecycle — hard bounds on render size and texture dimensions enforced
  before any GL allocation; a `WRONG_THREAD` failure when a non-render thread touches the layer.

## Protocol (`effects-protocol`)

- `EffectsProtocol` — schema version constant and `maxRequestBytes` (1 MiB), matching the
  runtime's framing discipline.
- `EffectsJson` — a closed Jackson `ObjectMapper` (no default typing, `FAIL_ON_UNKNOWN_PROPERTIES`,
  bounded depth/string/number tokens) for all request/response types.
- Closed request/result records: `CompileRequest`/`CompileResult`, `PreviewRequest`/`PreviewResult`,
  `CompareRequest`/`CompareResult`, `ListResult`, `CapabilitiesResult`. `PreviewResult` carries a
  bounded artifact reference (opaque receipt, not a filesystem path) plus pixel metrics.
- `EffectsProtocolService` — process-local registry of declared effects, publishing stable
  non-secret effect ids and routing compile/preview/compare to the owning layer. Mirrors the
  harness/runtime session-registry pattern.

## MCP surface (`effects-mcp`)

One closed stdio server, tool names are the catalog contract. v0.1 tools:

| Tool | Purpose |
| --- | --- |
| `effect_capabilities` | Discover supported operations |
| `effect_list` | List declared effects |
| `effect_compile` | Compile an effect into structured diagnostics |
| `effect_preview` | Deterministic render to a bounded PNG artifact plus pixel metrics |
| `effect_compare` | Tolerance/region-mask pixel comparison of two previews or preview vs reference |

Bounds, unknown-field rejection, and stable typed errors apply everywhere. No filesystem, shell,
reflection, script, expression, or network operation is exposed.

## Fixture (`effects-fixtures`)

A deterministic `Lwjgl3Application` that, under Xvfb: builds an `EffectsLimits.developmentDefaults()`
instance, declares one known-good and one known-bad effect, compiles both into structured
diagnostics, renders the good one to a preview, runs a self-comparison and a deliberate
divergence, writes the PNG, and exits 0. It is the real-GL proof that the Java API and the
diagnostic/preview/comparison path work end-to-end, and is the Linux-native CI gate.

## Data flow

```text
game/test/agent
  -> EffectDescription (core, immutable)
  -> EffectCompiler (libgdx, render thread) -> ShaderDiagnostic (core)
  -> PreviewRenderer (libgdx) -> RgbaImage (core) -> PNG artifact
  -> PixelComparer (core) -> PixelComparisonResult (core)
  -> protocol -> MCP tool result (bounded JSON)
```

Compilation and preview are request/response on the render thread (routed through the application's
render scheduler, never read off-thread). Pixel comparison is pure JDK math and may run on any
thread.

## Determinism, boundedness, security

- **Determinism:** fixed resolution, fixed `u_time`, fixed input textures, fixed geometry, stable
  message/region ordering. A repeated preview of the same description is byte-identical.
- **Boundedness:** every string, collection, shader source, uniform list, diagnostic, region list,
  image, and result has a configured limit with explicit truncation/eviction; oversized input is
  rejected, never silently accepted.
- **Security:** stdio MCP only, closed schemas, no network listener, no reflection/scripts/class
  loading, no caller-selected filesystem access. GLSL source is handed to the driver for
  compilation only after length/pass bounds; the library executes no JVM code from input. Pixel
  comparison reads only captured framebuffer buffers.
- **Thread model:** core/protocol are thread-safe (immutable values); libgdx layer is
  render-thread-confined and fails fast with `WRONG_THREAD` otherwise.

## Testing strategy

- `effects-core`: pure JDK tests for limits validation, defensive copying, diagnostic parsing over
  fixture log strings (including truncation and unknown line numbers), and pixel comparison over
  deterministic `int[]` fixtures (equal, differing, masked, tolerance boundaries, dimension
  mismatch).
- `effects-protocol`: round-trip, unknown-field rejection, version rejection, depth/string bounds.
- `effects-libgdx`: real-GL tests under Xvfb (compile known-good/known-bad, preview determinism,
  pixel capture correctness); backend-neutral tests for non-GL helpers.
- `effects-mcp`: closed-schema and tool-catalog tests against the protocol service.
- `effects-fixtures`: end-to-end real-GL fixture (Linux CI gate; compile-only on Windows/macOS).

## Versioning and ADRs

Development version `0.1.0-SNAPSHOT`. Schema version embedded in the protocol envelope and rejected
when unsupported. The first two ADRs accompany the first implementation task: ADR 0001 (render-thread
confinement and hand-rolled FrameBuffer passes over third-party effects libraries) and ADR 0002
(bounded declarative effect model with structured diagnostics as the primary interface).

## Open questions (resolved during implementation, not blocking)

- Exact default limit values are set in `EffectsLimits.developmentDefaults()` and tuned by the
  fixture; the schema (field names/types) is fixed here.
- PNG artifact store policy (quota, expiry) is borrowed from the harness `FileArtifactStore`
  pattern and specified in the plan.
